## 1. 目的とスコープ

### 1.1 目的
大型コンバインの**外観**と**内部の作物処理の流れ**を、ブラウザで回転・分解・断面表示しながら理解できる3Dモデルを作ります。見た目のリアルさよりも「各パーツの形・位置・動きが実機に対して破綻していないこと」を優先します。

### 1.2 スコープ

| 区分 | 含める | 含めない（将来課題） |
|---|---|---|
| 機体 | 単一アキシャルロータ機 1機種（汎用デザイン） | ツインロータ／ハイブリッド／コンベンショナル（§11 で拡張方針のみ） |
| ヘッダ | ドレーパーヘッダ 40ft（既定）、コーンヘッド 12条（切替） | オーガプラットフォーム、ヘッダトレーラ |
| 走行 | ホイール（前シングル） | クローラ仕様、物理エンジンによる走行 |
| 動き | 回転・往復・昇降・展開などの運動学的アニメーション | 作物の物理シミュレーション（粒子は決めた経路を流すだけ） |
| 表示 | 外観／X線／断面／分解／作物フロー | VR、モバイル最適化（動作はするが目標外） |

### 1.3 ブランドの扱い
- 実在メーカーのロゴ・商標・機種名・固有の配色の組み合わせは使いません。参考にした機種の**寸法とメカニズム**だけを使います。
- 既定の配色は、主要農機ブランドの塗装から離れた「ティール `#2A7B78` ＋ オフホワイト `#ECEAE4` ＋ 足回りダークグレー `#2B2E31`」とします。
- `livery` は差し替え可能ですが、**実在ブランドの配色をプリセットとして同梱しません**。資料01 §6 の色の値は調査記録であり、実装には使いません。
- UI・ラベルに機種名は出しません（説明パネルの出典表記を除く）。

## 3. 座標系・単位

- 単位：**メートル**、角度は内部ではラジアン（spec ファイルでは度で書き、読み込み時に変換）
- **右手系**：`+X = 前進方向`、`+Y = 上`、`+Z = 機体の右側`
  - 資料04 は「z は左が正」としていますが、x前・y上の右手系では +z は右になります。本設計はこちらに統一します（R-01）。
- **原点**：前車軸中心の真下の地面、機体中心線上
- 「左」＝ −Z ＝ 乗降ラダーと排出オーガがある側
- **寸法表記**：`{x, y, z}` の順（前後 × 上下 × 左右）。表の「寸法」列もこの順です（R-11）。

### 4.3 干渉・外形の自動検査（R-09）
干渉ルールを手で列挙するのはやめ、**spec から作った簡易形状の全組み合わせ**を自動で検査します。

1. **簡易形状**：各部品に OBB または円柱（回転体）を spec から生成。可動部は自身のピボットからの変換を持つ。
2. **全ペア検査**：意図的に接する組（ロータとケージ、エレベータとオーガの接続部など）だけを**許可リスト**に書き、それ以外の重なりはすべて失敗とする。必要な最小隙間（既定 0.05 m）も検査する。
3. **スイープ**：可動部は範囲を 1° 刻み（直動は 1 cm 刻み）で動かして検査する。
   - フィーダ −1.2°〜+12°、フェース前後チルト ±8.5°（全幅 17°）、左右チルト ±4°、リール上下・前後
   - 排出オーガ 0〜95°、タンクフラップ 0〜110°、後輪操舵 ±32°、ラダー折り畳み（M1）
4. **外形エンベロープ**（輸送状態）：全高 ≤ 4.00、全幅 ≤ 3.96、全長 ≤ 10.15。
5. **地面**：刈刃 y ≥ 0（全昇降範囲）、最低地上高 ≥ 0.30。
6. **機能上の不変条件**
   - ロータ半径 ＜ わらの経路半径 ＜ ケージ内径（R-13）
   - コンケーブ下端 − グレインパン上端（振幅込み）≥ 0.10
   - テーリングオーガの x がシーブ後端とチャッファ延長部後端の間（R-06）
   - タンク容量（延長展開・平ら）が 14.1 m³ ± 5%
   - 排出オーガ展開時の吐出口高さ ≥ 4.3 m、横方向の到達がヘッダ端 ＋ 1.0 m 以上
   - 昇降シリンダの長さが全昇降範囲で「最短長 ≤ 長さ ≤ 最短長 ＋ ストローク」

## 5. パーツ階層（シーングラフ）

可動部は「**ピボット Group（原点＝回転軸）→ 子メッシュ**」にそろえ、アニメーションはピボットの `rotation`／`position` だけを動かします。

```
Combine (root, 原点=前車軸直下の地面)
├─ Chassis
│  ├─ Frame / SidePanels (L, R)          … 閉じたソリッド。X線・断面の対象
│  ├─ FrontAxle ─ Housing ; WheelPivot.L/R (回転軸 z) ─ Tire, Rim
│  ├─ RearAxle ─ Beam ; SteerPivot.L/R (yaw) ─ WheelPivot (z) ─ Tire, Rim
│  ├─ LiftCylinder.L/R                   … Chassis 側に置き、毎フレーム両端点を追従（§6.4）
│  ├─ Cab ─ Glass, Seat, Mirrors, Lights, GPS ; LadderPivot ─ Ladder
│  ├─ GrainTank ─ Body ; FlapPivot[0..3] ─ Flap ; CornerPiece[0..3] ; BubbleUpAuger ; CrossAuger ; GrainPile
│  ├─ UnloadSystem ─ VerticalAuger ; TurretPivot (傾いた軸回りの回転) ─ Tube ─ Flighting ; SpoutPivot (pitch) ─ Spout
│  ├─ Engine ─ Block, Exhaust ; RotaryScreen (spin)
│  ├─ Thresher        … 内部系
│  │  ├─ RotorPivot (spin) ─ Core, Impeller, RaspBars(Instanced)
│  │  ├─ Cage ─ TopCover(+HelicalVanes), Concave, SeparatorGrate
│  │  └─ DischargeBeater (spin)
│  ├─ CleaningShoe
│  │  ├─ Fan (spin)
│  │  ├─ UpperShoe (oscillate) ─ GrainPan, Chaffer, ChafferExtension
│  │  ├─ LowerShoe (oscillate, 逆位相) ─ Sieve
│  │  ├─ CleanGrainAuger (spin) ; TailingsAuger (spin) ; TailingsReturn
│  │  └─ CleanGrainElevator (パドル)
│  └─ Residue ─ Chopper (spin) ; ChaffSpreader.L/R (spin) ; StrawSpreader.L/R (spin, 逆回転)
├─ FeederPivot (pitch：ヘッダ昇降)
│  ├─ FeederHousing ─ SlatChain
│  └─ FaceplatePivot (前後チルト) ─ LateralTiltPivot (左右チルト)
```

### 5.1 実装上の決まり（R-19）
- **更新順序**：毎フレーム ①状態の補間 → ②全ピボットの回転・位置を設定 → ③`root.updateMatrixWorld()` → ④リンク機構（シリンダ）と粒子の位置計算。③を挟まないと端点が 1 フレーム遅れる。
- **向き合わせ**：`CylinderGeometry` の軸は +Y、`lookAt` は +Z を向けるため、シリンダは `quaternion.setFromUnitVectors(Y, dir)` で向きを決める。リンク機構の祖先には不均一スケールを置かない。
- **UV スクロールの部品**（ドレーパー、フィーダチェーン、エレベータ）は Texture を部品ごとに `clone()` する。左右のドレーパーは UV を反転して中央へ流す。
- **地速の表現**：機体は原点に固定し、**地面（と圃場の作物）をスクロール**させる。車輪の回転は地速から計算する。

## 6. 動き（運動学）

### 6.1 状態モデル
すべての動きは1つの `MachineState` から決めます（UI はこの値を変えるだけ）。

```ts
interface MachineState {
  engineOn: boolean;
  separatorOn: boolean;   // 脱穀部（ロータ・ファン・シュー・チョッパ）
  headerOn: boolean;      // ヘッダとフィーダ
  unloadOn: boolean;      // 排出オーガの回転と穀粒の流出
  groundSpeed: number;    // km/h（0〜12、収穫時 5〜8 を想定）
  headerAngle: number;    // deg（−1.3〜+12）
  reelHeight: number;     // 0..1
  reelIndex: number;      // リール周速 / 地速（1.1〜1.25）
  steerAngle: number;     // deg（±35）
  augerDeploy: number;    // 0..1（0=格納、1=95°）
  tankFlaps: number;      // 0..1
  tankFill: number;       // 0..1
  timeScale: number;      // 再生倍率（§6.3）。既定 0.1
  mechanismView: boolean; // true＝部品ごとの減速を許す「機構観察モード」（§6.3）
}
```

`augerDeploy`、`tankFlaps`、`headerAngle` などは目標値への一次遅れ（ダンピング付き補間）で動かし、油圧の「じわっと動く」感じを出します。

### 6.3 時間スケールとストロボ対策（R-08、R-25）

**時間スケールは1つ**にします。作物フローと機構は同じ `timeScale` で動き（重力にも同じ倍率を掛ける）、UI に「再生速度：実時間の 1/10」のように実際の倍率を表示します。既定は 0.1。

高速回転体は、時間スケールを掛けてもストロボ（逆回転や静止に見える現象）が出ることがあります。判定と対処は次のとおり。

1. 部品ごとに spec で**繰り返しピッチ**（羽根・ナイフ・ラスプバー・パドルの角度ピッチ、または直線ピッチ）を持つ。
2. 毎フレーム、実測の `dt` で 1 フレームの移動量を計算し、**ピッチの半分以上なら**その部品を「ブラー表示」に切り替える。
   - 回転体：羽根を隠し、回転面に半透明のディスク（放射状のグラデーション）を表示
   - 直動（チェーン・ベルト）：テクスチャを流れ方向にぼかした版に切り替える
3. 例（60 fps、timeScale 0.1）：ファン 1,000 rpm → 100 rpm → 1 フレーム 10°、ピッチ半分 4.5°（40 枚）なのでブラー表示。ロータ 1,000 rpm → 10°/フレーム、ラスプバー列のピッチ半分 45°（4 列）なので通常表示。
4. **機構観察モード**（`mechanismView`、作物フロー非表示時のみ）では、部品ごとに個別の減速を許し、羽根が見える速度まで落とせる。このとき UI に部品ごとの倍率を表示する。

### 6.4 リンク機構
- **フィーダ昇降シリンダ**：本体は Chassis 側のアンカー、ロッド先端はフィーダ側のアンカー（§4.2 (b)）。§5.1 の順序で両端点のワールド座標を取り、本体の向きを合わせ、ロッドを `distance − bodyLength` だけ伸ばす。
- **排出オーガ**：縦オーガの軸を前方へ 12° 傾け、横管はその軸に対して格納時に水平になる角度で固定する。ヨー回転すると横管が持ち上がり、95° で仰角約 12°、吐出口 4.86〜5.00 m になる（計算は `docs/review.md` 付録）。
- **後輪操舵**：左右同角。
- **リール**：昇降アームのピボット回転と前後スライドを独立パラメータにする。

## 7. 作物フロー（粒子）表現

物理シミュレーションはせず、**部品ごとに決めた経路に沿って粒子を流す**方式にします。

### 7.1 流れの種類と経路

| 流れ | 色 | 経路 |
|---|---|---|
| 刈った作物 | 黄土 | 刈刃 → サイドドレーパー（横→中央） → センタードレーパー → フィードドラム → フィーダ（下送りで後上方へ） → ロータ入口 |
| わら | 薄茶 | ロータ周りのらせん（半径 **0.36**、約 9 周） → ディスチャージビータ → チョッパ → ストロースプレッダから後方に扇形（±60°）に散布 |
| 穀粒 | 金色 | コンケーブ・グレートから落下 → グレインパン（後方へ） → チャッファ → シーブ → クリーングレインオーガ（右へ） → エレベータ（右側を上昇） → バブルアップオーガ → タンク中央に落下・堆積 |
| 籾殻（チャフ） | 灰白 | シュー上でファンの風に乗って後方へ（3〜6 m/s） → チャッファ後端を越える → **チョッパの下**を通ってチャフスプレッダ → 地面へ（R-30） |
| 2番（テーリング） | 橙 | **チャッファ延長部を通り抜けた物 ＋ シーブの上を後端まで流れた物** → テーリングオーガ（右へ） → 還元エレベータ（リスレッシャ） → グレインパン前部へ戻る（R-06） |
| 排出 | 金色 | タンク底クロスオーガ → 縦オーガ → 横管 → スパウト先端から放物線落下（初速 1.5 m/s ＋重力）→ 地面またはトレーラで消滅 |

### 7.2 実装
- 流れごとに `InstancedMesh` を 1 つ（粒子は低ポリの楕円体または短冊）。全体の上限 8,000 粒。`frustumCulled = false` にする（バウンディング球は自動更新されないため、R-19）。
- 経路は区間ごとに**その区間を持つ部品のローカル座標**で定義し、毎フレーム部品の `matrixWorld` で変換する。ヘッダ昇降・分解表示・チルトに粒子が追従する（R-19）。
- 粒子は `{ flowId, segment, t, offset }` を持ち、区間ごとの速さ（ベルト速度・風速など、§6.2）× `timeScale` で進める。
- 発生量は `groundSpeed × ヘッダ幅 × 収量係数` から決める。`separatorOn` が off なら脱穀以降の流れを止める。
- タンクの穀粒の山はメッシュで表現する。タンク内面に沿った角柱に、四角錐の屋根（安息角 25°）を載せた形を `tankFill` で伸縮させる（R-29）。粒子はタンクに入った時点で消して山を高くする。
- 排出中は `tankFill` を「排出速度 150 L/s ÷ 容量 13.9 m³」の割合で減らす（実時間で約 93 秒で空になる）。

## 9. ジオメトリとマテリアル

### 9.1 作り方の方針
- **すべてコードで生成**（プロシージャル）。外部の3Dモデルファイルは使わない。寸法は `spec`（§10）から読む。
- 外板：`Shape` → `ExtrudeGeometry`（`bevelEnabled`）。**閉じたソリッド**として作る（断面キャップのため、R-15）。
- 回転体：`CylinderGeometry`、らせん（オーガのフライト）は `TubeGeometry` か専用のらせん面ジオメトリ。
- 繰り返し部品は `InstancedMesh`：タイン、ナイフガード、ラスプバー、フィーダスラット、タイヤのラグ、コーンヘッドのロー。
- **ジオメトリの結合**は「同じ Part・同じマテリアル・同じ layer」の範囲に限る。`mergeGeometries` はインデックス付きとなしが混在すると失敗するので、結合前に `toNonIndexed()` でそろえる（Extrude はインデックスなし、Box・Cylinder などはあり）。結合後も `userData.partId` を残す（R-17）。

### 9.2 主要部品のつくり

| 部品 | 方法 |
|---|---|
| タイヤ | `LatheGeometry`（断面の輪郭を回転）＋ラグを InstancedMesh（V 字＝R1W 相当）。遠景 LOD ではラグを法線マップに |
| ホイールリム | Lathe ＋ 穴あきディスク（Shape の穴） |
| キャブ | フレームを細い Box で組む。ガラスは既定で `transparent` ＋環境マップ反射。高品質設定のみ `MeshPhysicalMaterial`（transmission）を使う（R-16） |
| グレインタンク | 外箱＋ V 底（台形断面の Extrude）。フラップは薄い Box をヒンジ Group に、角にコーナーピース |
| 排出オーガ | 縦管＋エルボ（`TorusGeometry` の 1/4）＋横管＋スパウト |
| ロータ | 芯は Cylinder、前端は円錐台＋三角羽根 3 枚、ラスプバーはらせん配置の Instanced Box |
| コンケーブ | 150° の円弧格子：周方向の細い Box × n と、円弧のリブ（Torus 片） |
| リール | 中心パイプ＋スパイダアーム（Box）＋バット 6 本（Cylinder）＋タイン Instanced |
| ドレーパー | 平面＋スクロールテクスチャ（`CanvasTexture` で白いスラットを描く、部品ごとに clone） |

### 9.3 マテリアルと光
- PBR（`MeshStandardMaterial`）が基本。塗装は roughness 0.45 / metalness 0.2、ゴム・樹脂は roughness 0.9。
- 環境光：`RoomEnvironment` を `PMREMGenerator` で IBL に。主光源は `DirectionalLight`。
- 影は `PCFShadowMap` ＋ `shadow.radius`（r185 では `PCFSoftShadowMap` は非推奨、R-18）。影を落とすのは外形の大きな部品だけ。
- 色は `livery` にまとめる（本体・フレーム・ヘッダ・アクセント・ガラス）。

### 9.4 性能予算と検証（R-24）

| 項目 | 目標 | 検証方法 |
|---|---|---|
| 三角形数 | 300k 以下（外観のみ 150k 以下） | CI：`renderer.info.render.triangles` |
| ドローコール | 外観モード 250 以下（影・ステンシルの追加パスを含めた実測値） | CI：`renderer.info.render.calls` |
| フレームレート | 基準機（Intel Iris Xe 相当、1920×1080、DPR 1）で 60 fps、粒子 8,000 時に 45 fps 以上 | 手動計測（ヘッドレス Chromium はソフトウェア描画のため CI では測らない） |
| 初回表示 | 2 秒以内 | 手動計測 |

## 16. 圃場と小麦：本当に刈り取れるかの検証（計画）

### 16.1 目的
これまでの検査は「部品同士がぶつからない」ことの確認だった。ここでは、実際の小麦の畑で**この機械が仕事として成り立つか**を確かめる。具体的には「刈れるか（ヘッダと作物の位置関係）」「流し切れるか（各段の処理能力の釣り合い）」「回せるか（タンクが満杯になる時間と排出）」の 3 つ。

### 16.2 進め方（2 段階）

### 16.5 小麦の 3D モデル（段階 2）
- **1 本の小麦**：茎（数節の細い円柱を曲げる）、穂（粒の並びを表す小さな楕円体の列）、葉（細い板 2〜3 枚）。熟期の色（麦わら色〜黄金色）。
- **株のまとまり**：茎を 20〜30 本まとめた「株」を 1 インスタンスにして並べる。40 ft ヘッダで 100 m 刈ると約 1,200 m²、穂数 500 本/m² で 60 万本になるため、1 本ずつは描かない。カメラの近くだけ 1 本ずつ、遠くは板（ビルボード）に切り替える。
- **風と接触**：頂点シェーダで穂先を揺らす。リールのタインとデバイダが近づいた株を押し曲げる。
- **刈り取り**：圃場を 0.25 m 角のセルに分け、刈刃が通ったセルを「刈り株（高さ＝刈高さ）」に切り替える。刈った量を作物フローの発生量にする。
- **機体は原点に固定し、圃場をスクロールさせる**（§5.1 の方針どおり）。

- 記録：刈った面積、収穫量、タンク充填の推移、排出の回数と時間、各段の負荷率（能力に対する割合）、W-1〜W-7 の結果。

### 16.7 段階 1 の結果（v0.5）

**資料**：`docs/research/05-wheat.md`（小麦）、`docs/research/06-capacity.md`（段ごとの処理能力）。spec に `crop.wheat` と `capacity` を加えた。能力の値は多くが PAMI の実測からの逆算による**推定**。

**実装**：`src/model/harvest.ts`（W-1〜W-6 の計算）、`tests/harvest.test.ts`、画面右下の「収穫の成立チェック」パネルと「作物（小麦）」の操作（収量・草丈・MOG 比、リールを推奨位置へ、最大速度に合わせる）。

**計算のしかた**
- 投入量：穀粒 ＝ 収量 × 作業幅 × 地速、総量 ＝ 穀粒 ×（1 ＋ MOG/穀粒）。MOG/穀粒 は刈高さから推定（PAMI 系の試験：10 cm 1.20、25 cm 0.85、40 cm 0.64）。
- 各段の能力：フィーダ（幅 × 87 t/h/m）、ロータ（分離面積 1.67 m² × 10.5 kg/s/m²）、シュー（選別面積 4.58 m² × 穀粒 2.55 kg/s/m²）、機械全体（Class 8 の実績 72 t/h）、エレベータ（135 t/h）、排出（150 L/s）。面積は spec の形から計算する。
- 最大速度 ＝ 各段が能力いっぱいになる地速の最小値。その段がボトルネック。

**結果**（作業幅 12.19 m）

| 条件 | 最大速度 | ボトルネック | 次に厳しい段 |
|---|---|---|---|
| 4.5 t/ha・刈高さ 10 cm（MOG 1.20） | 5.2 km/h | ロータ | 機械全体 6.0 |
| 4.5 t/ha・刈高さ 25 cm（MOG 0.85） | 6.2 km/h | ロータ | 機械全体 7.1 |
| 8 t/ha・MOG 0.80（資料 06 と同じ条件） | 3.6 km/h | ロータ | 機械全体 4.1、シュー 4.3 |
| 8 t/ha・刈高さ 10 cm | 2.9 km/h | ロータ | 機械全体 3.4 |

- 資料 06 の推定（Class 8 で 8 t/ha なら約 4 km/h、ロータが最も厳しい、ロータ単独で 2.8〜3.8 km/h）と合う。
- 基準の小麦（4.5 t/ha、草丈 0.80 m、刈高さ 25 cm、5 km/h）では W-1〜W-6 がすべて成立。タンクは約 23 分で満杯、排出 91 秒（比 7%）。
- エレベータと排出オーガは、どの条件でもボトルネックの 2 倍以上の余裕がある。

**チェックで見つかり、直したこと**
| 見つかったこと | 対応 |
|---|---|
| 背の低い小麦（草丈 0.56 m）を刈高さ 25 cm で刈ると、リールを一番下げてもタインが目標の高さ（作物の上から 1/3〜1/2）に届かない（W-2） | ドレーパーデッキの厚さを 0.20 → 0.14 m（上端 y 0.30 → 0.24）にし、リールの下限を −0.15 → −0.22 m に広げた。干渉のスイープは全範囲で通る |
| 既定の地速 6 km/h は、刈高さ 10 cm の基準の小麦で処理能力（5.2 km/h）を超える（W-4） | 既定の地速を 5 km/h に（Class 8 の小麦での実例 4.8〜6.4 km/h）。画面で ✗ と、どの段が詰まるかを示す |
| 選別面積 4.58 m² は参照機（S790 の 5.9 m²）より小さい。前段チャッファを省略しているため | 今の条件ではシューはボトルネックにならない（ロータが先）ので形は変えず、記録だけ残す（M3 で前段チャッファを足すかを決める） |

**限界**：能力の値は 1 機種（X9）の PAMI 実測からの逆算が中心で、Class 8 の単一ロータ機の実測ではない。損失（%）は計算していない（「損失 1% の能力」を超えるかどうかだけを見ている）。

## 17. M2 の結果（v0.5）

### 17.1 運転状態と時間
- `src/model/machine.ts`：運転状態（エンジン・ヘッダ・脱穀選別部・地速・リール周速比・再生倍率）から、各部の実機の速さ（車輪・リールの角速度、ナイフとシューの振動数、ドレーパーの速さ、地面の流れ）を計算する。描画から切り離した純粋な計算で、`tests/kinematics.test.ts` で向きと値を確かめる。
- **時間の扱い**：回転・往復・ベルトなど機械の工程は再生倍率（既定 0.1）を掛けて動かす（R-08 の「1 つの時間スケール」）。**油圧で動く姿勢（フィーダ昇降・排出オーガ・フラップ・操舵など）は実時間**で、§6.2 の所要時間（オーガ 0→95° を 8 秒など）で目標へ近づける。油圧の動きは作物の流れと速さを合わせる必要がなく、0.1 倍にすると操作に 80 秒かかって使いにくいため。画面の表示にもこの区別を書いている。

### 18.3 表示
- **分解表示**：「表示 → 分解」で 0〜1。部品群ごとに前・上・横へ離す（ヘッダは前へ 3.2 m、タンクは上へ 2.8 m など）。分解中は干渉検査を止める。

- 断面・X線・分解に切り替えると、収穫チェックのパネルを自動で閉じる（中を隠さないため）。
